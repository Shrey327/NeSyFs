How these tasks work

Every method receives the same initial layout and command rules. Later observations contain action outcomes, so agents must retain relevant state. The kitchen changes deterministically in response to actions; there are no autonomous or timed disturbances. Complex goals can require a key, washing, multiple objects, and restoring a door or tap.

Success is checked against the environment’s actual goal state, including any required cleaning or restoration. Planning only occurs if reflection rejects proposals and is not guaranteed to be used.

A rejected decision consumes one opportunity. Model and settings are recorded with every run.

03 / INTERPRETATION

Useful evidence,
not a final verdict.

Controlled comparison

Every configuration receives the same selected tasks, provider, model and decision budget. Episodes use fresh environment state and isolated graph sessions. Earlier runs may use a different scenario version and should not be pooled.

Measure the limits

Small, stochastic pilot runs are demonstrations—not statistical proof. Model output, latency, and costs can vary. Reference solutions are feasible examples, not proven shortest paths.

Paper results are separate

This independent implementation and toy environment do not reproduce the paper’s benchmark results.
